# EOKKA 구조 리팩터링 기록

작업일: 2026-10-12

## 배경과 목표

기능을 빠르게 추가하면서 대시보드에 차트, 기간 집계, 수익률 비교,
카드 애니메이션이 모였고 분석 결과 화면에는 투자위원회 설명과 여러 차트가
함께 들어 있었다. 작은 변경에도 큰 파일을 읽어야 했으며, 계산 함수를
검증하려면 화면 또는 서버 모듈을 가져와야 했다.

이번 작업에서는 기존 계산식과 표시 구조를 유지하면서 변경 이유가 다른 코드를
분리했다. 파일 수 감소나 성능 수치를 목표로 삼지 않았다. 기능을 찾기 쉬운 위치,
서버와 화면 사이의 명확한 경계, 외부 서비스 없이 검증 가능한 계산이 목표다.

## 의존성과 중복 정리

- 투자 인사이트가 대시보드 라우트를 직접 가져오던 의존성을 제거하고
  `HistoricalInsights` 컴포넌트를 함께 사용한다.
- 익명 종목명 복원과 투자위원회 투표 테스트는 UI 또는 OpenAI 호출 모듈 대신
  해당 순수 함수만 가져온다.
- `PortfolioTrade`는 계산에 필요한 최소 필드만 정의한다. 계산이 DB 조회 함수의
  반환 타입에 종속되지 않는다.
- `service-limits.ts`에서 종목 수, 일일 분석 수, IP 제한, 상세 기록 수를 관리한다.
  빠른 분석 UI와 서버 검증, 정밀 분석, 매매일지, 기록 정리에서 같은 값을 사용한다.
  안내 문장 전체를 동적 템플릿으로 바꾼 것은 아니므로 정책 변경 시 문구도 검토한다.
- `invalidateAnalysisRouteData()`로 분석 관련 캐시 무효화를 통일했다.
  빠른 분석 완료, 정밀 분석 완료, Pro 체험 전환 시 프로필·도전과제도 함께 갱신한다.
- 정밀 분석 서버의 Pro 권한 확인 이후 실행될 수 없던 무료 사용자 분기를 제거했다.
- 기존 서버 진입 파일은 필요한 함수를 재수출하여 기존 호출부와의 호환성을 유지한다.

## 검증

- 리팩터링 전 단위 테스트: 33개 통과.
- 리팩터링 후 단위 테스트: 47개 통과.
- 타입 검사와 클라이언트·서버 배포 빌드 통과.
- Chromium 공개 페이지 및 비로그인 접근 제어 테스트: 11개 통과.

추가 테스트는 매수 위치 경계값, 복리 계산, 고점 기준 낙폭, 공통 월의 가중 수익률,
월 적립 시뮬레이션, 휴장일/미갱신일 구분, 기간 집계, 부분 매도 원금,
환율별 현금흐름, 월말/윤년 구독 날짜, 분석 캐시 무효화를 확인한다.

인증된 사용자로 하는 전체 브라우저 시나리오, 실제 결제 승인, 유료 AI 요청은
이번 자동 검증에 포함하지 않았다. 테스트 통과가 모든 업무 흐름의 완전한 검증을
의미하지는 않는다. DB 스키마 변경과 운영 배포도 이번 작업에는 없다.

## 포트폴리오에 사용할 설명 초안

> 기능 확장 과정에서 대시보드가 4천 줄 이상으로 커지면서 UI와 계산 로직이
> 결합되는 문제가 생겼습니다. 날짜별 집계와 수익률 계산을 순수 함수로 추출하고,
> 차트·요약 카드·투자위원회를 기능별 컴포넌트로 분리했습니다. 또한 화면과 서버의
> 사용량 정책을 공통화하고 분석 결과 변경 시 관련 캐시를 일관되게 갱신하도록
> 정리했습니다. 변경 과정에서 단위 테스트를 33개에서 47개로 확장하고 배포 빌드와
> 11개 공개 페이지 테스트로 회귀 여부를 확인했습니다.

AI 도구를 활용한 구현·검증 작업이므로 본인의 설계 판단과 도구의 기여를 구분해서
설명한다. 면접에서는 분리 전의 어려움, 경계를 선택한 이유, 테스트가 보장하는
범위와 보장하지 못하는 범위를 직접 설명할 수 있어야 한다.

## 유지보수 기준

화면 파일은 라우트와 화면 조립을 맡고, 사용자 행동에 밀접한 상태는 해당 화면에
남긴다. 계산은 순수 함수, DB와 비밀키 처리는 `.server.ts`, 여러 화면에서 공유하는
기능은 해당 기능 폴더에 둔다. 줄 수만 줄이려고 서로 밀접한 상태를 잘게 나누지 않는다.

홈과 운영 관리에는 여전히 큰 폼과 모달 흐름이 있다. 다음 변경에서 해당 흐름을
수정하게 되면 입력 상태 및 제출 과정을 별도 훅이나 컴포넌트로 분리하고, 인증된
브라우저 시나리오를 추가해 검증 범위를 넓힐 수 있다.
