# 운영 관리

관리자 화면: `/dashboard/admin`. 문의: `/contact`.

- 문의는 로그인한 사용자가 접수하며 글과 운영팀 답변은 누구나 볼 수 있습니다. 작성자 이름은 공개 화면에서 일부 가려 표시됩니다.
- 문의 접수는 관리자 알림, 운영팀 답변은 작성자 알림으로 전달됩니다. 문의 작성자는 종료 전까지 추가 댓글을 작성할 수 있습니다.
- 문의글은 작성자와 관리자가 삭제할 수 있습니다. 추가 댓글은 작성자 본인과 관리자가 삭제할 수 있으며, 최초 문의 내용은 문의글 전체 삭제로만 지울 수 있습니다.
- 전체 공지는 확인 모달 후 기존 모든 프로필의 알림함으로 발송됩니다. 이메일·푸시 발송 기능은 아닙니다.
- 사용자 메뉴는 검색, 가입일, 최근 활동일, 무료/Pro 상태를 조회합니다. 정지·계정 삭제·권한 변경 기능은 제공하지 않습니다.
- 문의는 최근 100건, 공지는 최근 20건을 표시합니다.

## 권한 부여

먼저 `npm run db:migrate`로 스키마를 적용합니다. 운영 DB의 `DATABASE_URL`은 신뢰할 수 있는 서버/관리자 환경에만 보관합니다.

1. 사용할 구글 계정으로 서비스에 로그인합니다.
2. Supabase Authentication → Users에서 본인의 **User UID와 이메일**을 확인합니다.
3. 운영 DB에 연결된 관리자 터미널에서 실행합니다.

```sh
npx tsx scripts/set-admin.ts grant USER_UUID VERIFIED_EMAIL
```

권한 회수:

```sh
npx tsx scripts/set-admin.ts revoke USER_UUID VERIFIED_EMAIL
```

구글 로그인 자체로 권한을 주지 않습니다. `admin_members`의 정확한 사용자 UUID가 권한의 기준이며, 사용자 수정 가능한 메타데이터·이메일 문자열·프런트엔드 상태는 권한 판단에 사용하지 않습니다. 같은 Supabase 프로젝트와 같은 계정을 배포 후에도 사용한다면 재등록할 필요가 없습니다. 프로젝트 또는 계정이 바뀌면 새 UUID를 명시적으로 등록하고 이전 권한을 회수합니다. 관리자 계정의 Google 2단계 인증을 활성화하세요.

모든 관리자 loader/action은 서버에서 매번 권한을 확인합니다. 관련 테이블은 RLS 및 anon/authenticated 권한 제거로 브라우저 직접 접근을 차단합니다. 문의 작성자는 서버에서 소유권을 검증하며, 상태 변경은 동일 출처 POST만 허용합니다. 전체 공지는 트랜잭션과 UUID 중복 방지로 공지/알림을 함께 저장합니다. 관리자 권한을 주는 웹 API는 없습니다.

## 확인

`npm run typecheck`, `npx tsx --test app/features/admin/validation.test.ts`.
배포 전 일반 계정으로 관리자 URL 접근(403), 다른 사람 문의 접근(404), 문의/답변 알림, 전체 공지 확인 모달을 점검하세요. 전체 공지 테스트는 별도 테스트 DB에서만 실행하세요.
